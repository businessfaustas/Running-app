# GroupPace

A social endurance-sports calendar. Runners and cyclists post upcoming workouts on a 24-hour
timeline as open invitations, so others can find training partners and join.

**What's in the app**

- **Discover:** 24-hour timeline (or map) of workouts for the next two weeks, filterable by run or
  ride. Tap an empty time to post a workout there.
- **Workout page:** meeting point map and directions, who's going with each person's usual pace,
  join/leave, host cancel, share link.
- **Group chat** per workout, for people who are going.
- **Post a workout:** six short steps: sport, time, distance and pace, vibe, meeting point (map pin,
  your location or a popular spot), group size.
- **Plans** (upcoming and past), **Chats** (all your workout chats), **Profile** (stats, usual
  paces, edit), other athletes' profiles, and sign in / create account.

**Preview mode.** Without Supabase settings the app runs entirely in the browser: sample athletes
and workouts around today, and anything you do (accounts, workouts, joins, messages) is saved on
that device only. Set the Supabase variables (below) to make it multi-user.

## Stack

| Layer          | Choice                                                                      |
| -------------- | --------------------------------------------------------------------------- |
| Web app (PWA)  | React 19 + Vite + TypeScript, Tailwind CSS v4, React Router                 |
| Data / state   | TanStack Query (server state) + Zustand (UI state)                          |
| Maps           | MapLibre GL via `react-map-gl` with OpenFreeMap tiles (no API key)          |
| API (optional) | Node.js + Express 5, validated with Zod                                     |
| Database & ORM | Supabase Postgres + PostGIS, Drizzle ORM / drizzle-kit migrations           |
| Auth, realtime | Supabase Auth (profiles auto-created), Supabase Realtime (chat, attendance) |

## Getting started

Requires Node 22+ and pnpm 10.

```bash
pnpm install
pnpm dev            # http://localhost:5173, preview mode, no backend needed
```

Other scripts: `pnpm test`, `pnpm typecheck`, `pnpm lint`, `pnpm build`.

### Running against a real database

1. **Start Supabase locally** with the [Supabase CLI](https://supabase.com/docs/guides/cli).
   Run `supabase init` once to create `supabase/config.toml` (the migrations already exist).
   Then run `supabase start`, followed by `supabase db reset`, which applies `supabase/migrations`.
   For a hosted project, use `supabase link` and then `supabase db push`.
2. **Configure and seed the API**
   ```bash
   cp apps/api/.env.example apps/api/.env   # DATABASE_URL defaults to local Supabase
   pnpm db:seed                             # 10 athletes, 15 workouts dated around today
   pnpm dev:api                             # http://localhost:4000
   ```
3. **Point the web app at the API**: `echo "VITE_API_URL=http://localhost:4000" > apps/web/.env.local`,
   then `pnpm dev`.

`pnpm db:migrate` (drizzle-kit) can apply the same migrations directly. The target database needs
the Supabase `auth` schema, the roles and the `supabase_realtime` publication, so use it against a
Supabase database.

### Changing the schema

Edit `apps/api/src/db/schema.ts`, then run `pnpm db:generate`. drizzle-kit writes a new
timestamped migration into `supabase/migrations`. Behaviour that drizzle can't model (triggers,
policies, publications) goes in a custom migration: run
`pnpm --filter @grouppace/api exec drizzle-kit generate --custom --name=<name>`.

## Data model

- **profiles**: one row per Supabase Auth user, created by the `on_auth_user_created` trigger.
  Columns: `name`, `avatar_url`, `bio`, `sports` (`running`/`cycling`), `default_paces` (jsonb),
  `strava_id`.
- **workout_slots** ("beacons"): `sport_type` (`RUN`/`CYCLING`/`GRAVEL`/`TRACK`), local `date`,
  `start_time` and `end_time`, `distance_km`, `target_pace`, `vibe_tag`, `meeting_point_name`,
  `location` (PostGIS `geometry(Point, 4326)`, GiST-indexed as `geography` for radius search in
  metres), `max_participants` (group size including the host; null means unlimited), and `status`.
- **slot_participants**: `(slot_id, user_id)`, `status` (`ACCEPTED`/`PENDING`), `joined_at`.
- **slot_messages**: the per-slot chat, published to Supabase Realtime.

Rules enforced in the database (see `supabase/migrations/*_triggers_rls_realtime.sql`):

- The host is automatically an accepted participant of their own slot.
- Joining a full, cancelled or completed slot is rejected. The slot row is locked, so concurrent
  joins can't overbook it.
- `status` switches between `OPEN` and `FULL` automatically as people join and leave, or when the
  host changes the capacity.
- RLS: signed-in users can browse slots and attendance. Users can only host or join as
  themselves. Hosts can't leave their own slot. Only accepted participants can read or post in a
  slot's chat.

## API

| Method | Path      | Notes                                                                                           |
| ------ | --------- | ----------------------------------------------------------------------------------------------- |
| GET    | `/health` | Liveness check                                                                                  |
| GET    | `/slots`  | `from`, `to` (`YYYY-MM-DD`, required); `sport=RUN,TRACK`; `lat`, `lng`, `radiusKm` (default 25) |

`/slots` returns `SlotSummary[]` (see `packages/shared/src/domain.ts`). The mock data source in the
web app returns the same shape.

## Maps

Maps use [OpenFreeMap](https://openfreemap.org)'s dark style: free, no API key, commercial use
allowed. To use Mapbox or MapTiler instead, set `VITE_MAP_STYLE_URL` to a style URL that includes
your key.

## Deploying (Vercel)

Set the project's Root Directory to `apps/web`. `apps/web/vercel.json` sends every path to
`index.html`, so links like `/workouts/<id>` work when opened directly.
